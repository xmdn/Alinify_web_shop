# Shared Memory Bank

Read the repository-root `AGENTS.md` first. The `memory-bank/` files are the
persistent context shared with ChatGPT/Codex.

Before any non-trivial task, read:

- `memory-bank/projectBrief.md`
- `memory-bank/architecture.md`
- `memory-bank/decisions.md`
- `memory-bank/activeContext.md`
- `memory-bank/progress.md`
- `memory-bank/plans/current-plan.md` if present

Do not trust conversation history as the latest project state. Do not invent
architecture. Existing scripts, `docker-compose.yml`, and the backend's canonical
docs outrank stale notes; correct the memory bank when they disagree.

After meaningful work, update the applicable memory-bank files in the same
working session. At minimum update `activeContext.md` and `progress.md`.
Append durable decisions to `decisions.md`; update `architecture.md` only when the
structure changed. Keep `plans/current-plan.md` honest about scope, blockers, and
verification.

Also respect the load-bearing constraints in `AGENTS.md`: test-store-only, no
implicit publication (`push` needs `-Push`), no bypassing Claid or empty category
metadata, and never run `docker compose down -v` without explicit authorization.

`config/mapping.json` and `mock-ups/categories.json` are generated by
`scripts/setup.*` — re-run the setup instead of editing them.

This checkout is a git repository (`main`, one commit, remote `origin`), but the
handoff is the shared filesystem and the memory bank rather than commits. Do not
commit or push on another agent's behalf unless asked, and remember that
uncommitted work has no revert safety net.
